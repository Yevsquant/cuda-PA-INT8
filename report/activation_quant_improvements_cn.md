# INT8 KV-Cache 项目进阶方案：激活量化与精度评估改进

> 本文用「费曼讲解法」写成：先用大白话和类比把问题讲清楚，再上数学和工程细节。目标是把这个项目从「能跑、误差大概 3%」推到「经得起真实分布和困惑度检验」的水平。

---

## 0. 先把舞台讲清楚：我们到底在量化什么？

把注意力计算想象成一次「查字典」：

- **Query (Q)**：你手里的查询词，每次解码现算出来，是新鲜的。
- **Key (K) / Value (V)**：字典里已经写好的内容，越聊越多，全部存在 KV-Cache 里。

KV-Cache 是显存大户。一个长上下文里 K/V 占的显存远超模型权重。所以我们把 K/V 从 FP16 压成 INT8 —— **显存直接砍半**。

我们项目目前的做法（已在 `tests/paged_decode_attn.py` 和 `kernels/paged_attention_v5/v6` 里实现）：

- **对称量化（symmetric）**：`s = max(|x|) / 127`，没有零点（zero-point）。
- **逐 token 粒度（per-token）**：每个 token×head 一个 fp32 scale。
- **Q 保持 fp32，只有 K/V 进 INT8**：所以打分时是 `dot(q_fp32, k_int8) · s_k`（见 `qk_dot_int8`）。

记住这三个特征，后面所有改进都是围绕它们打补丁。

---

## 1. 核心痛点：为什么 INT8 怕「离群值（outlier）」，而 FP8 不太怕？

### 1.1 用「尺子」理解两种数制

INT8 和 FP8 都是 8 个 bit（256 个刻度），区别在**刻度怎么摆**：

- **INT8 = 均匀刻度的钢尺**。0 到最大值之间，每一格一样宽。
- **FP8（E4M3）= 不均匀刻度的对数尺**。靠近 0 的地方刻度密，越往大越稀。

现在来个比喻。假设一组数大部分在 `[-3, 3]`，但有**一个**离群值是 `100`。

- 用 INT8：因为 `s = max(|x|)/127 = 100/127 ≈ 0.79`，每一格宽 0.79。于是 `[-3, 3]` 这一大堆「正常值」全被挤进了 `±4` 这几格里 —— **绝大多数有用信息只用了 256 格里的 8 格**，精度灾难性地浪费了。一个离群值毁掉了所有正常值。
- 用 FP8：对数尺天生「大数粗、小数细」，100 也能表示，3 附近照样有细刻度。**离群值不会拖垮正常值**。

**这就是 INT8 量化的命门：它对动态范围（最大值/最小值之比）极度敏感，而离群值会把动态范围撑爆。**

### 1.2 为什么「激活/输入」比「权重」更危险？

- **权重（weight）** 训练完就固定了，分布乖巧、可提前标定（calibration）。
- **激活（activation）/ KV** 是**跟着用户输入跑出来的**。用户随便输入一句奇怪的话，某些通道（channel）就可能炸出巨大的激活值。这是**运行时**才知道的，没法提前完美标定。

而且这不是随机噪声：研究反复发现，LLM 的激活离群值**集中在固定的少数几个特征通道（systematic outlier channels）**。尤其是 **post-RoPE 的 K**，旋转位置编码会把能量集中到特定维度，产生稳定的大通道。

> 我们项目现在只在 `N(0,1)` 高斯数据上测过 —— 这种数据**没有离群值、没有重尾**，所以报出来的 ~3% 误差是「理想天气下的成绩」，真实分布下大概率更差。这正是审稿意见第一条戳的点。

## 2. 激活量化离群值问题：几种解法（从易到难）

下面每个方案我都先讲「一句话直觉」，再讲「怎么用在我们这个 KV-Cache 项目里」。

### 方案 A：更细的量化粒度（per-token / per-channel）—— 最便宜的起手式

**直觉**：一把尺子量不准一群胖瘦差异巨大的人，那就**一人一把尺子**。

- 离群值集中在「通道」维度 → 对 **K 按通道（per-channel）** 量化，每个通道一个 scale，离群通道用大 scale，正常通道用小 scale，互不干扰。
- 离群值不集中在「token」维度 → 对 **V 按 token（per-token）** 量化即可。

**这正是 KIVI 论文的核心洞见：K 走 per-channel，V 走 per-token。**

**用在我们项目里的难点（必须讲清楚）**：
我们的打分是 `Σ_d q[d]·k[d]`，对 **head_dim 维度求和**。

- per-token 的 scale 在 head_dim 上是常数，所以能提到求和号外面：`s_k · Σ_d q[d]·k_int[d]`（我们现在就是这么干的，`qk_dot_int8` 很干净）。
- per-channel 的 scale **就在 head_dim 维度上变化**，提不出来：`Σ_d q[d]·k_int[d]·s_k[d]`。这意味着内层循环每个元素都要乘一个不同的 scale，**破坏了向量化点积的简洁性**，也增加了访存。

**工程折中**：K 不做全通道，而是做**「分组通道（grouped/channel-group）」**——把 head_dim 切成若干组，每组一个 scale。在「对付离群通道」和「内层循环开销」之间取平衡。这是一个非常适合做消融实验（ablation）的点。

---

### 方案 B：SmoothQuant —— 把难度从激活「搬」到权重

**直觉**：激活很刺头（有离群通道），权重很温顺。那就**让两边各退一步**：给激活的离群通道除以一个系数 `s` 让它变乖，同时把这个 `s` 乘回到对应的权重上，数学结果不变。

$$ Y = (X \cdot \text{diag}(s)^{-1}) \cdot (\text{diag}(s) \cdot W) = X W $$

离群通道的 `s` 取大一点，激活就被「压平」，INT8 就好量了；代价是权重那边稍微难量一点，但权重本来就好量，扛得住。

**用在 KV-Cache 的注意**：SmoothQuant 原本是给线性层 GEMM 设计的。在注意力里，对应的是 `Q·Kᵀ`。可以把平滑系数吸收进 Q（Q 是现算的、fp32 的，不进 cache），K 存平滑后的版本。**这能在不改 INT8 内核数据通路的前提下，把 K 的离群通道压下去**，性价比很高，建议优先试。

---

### 方案 C：混合精度分解（LLM.int8() 式）—— 离群值单独开小灶

**直觉**：99% 的值老老实实用 INT8，极少数离群值**单独拎出来用 FP16 算**，最后加回去。

因为离群通道是「系统性的、固定的少数几个」，开销其实可控。

**用在 KV-Cache 的难点**：这会让 cache 变成「INT8 主体 + FP16 稀疏离群」的混合存储，**显存收益打折、内核分支变复杂**。对追求干净高带宽内核的我们来说，这是「精度兜底方案」，不是首选，但值得在报告里作为对照（说明我们知道这条路、并解释为何不选）。

---

### 方案 D：旋转法（Hadamard / QuaRot / SpinQuant）—— 把离群值「摊平」

**直觉**：离群值的麻烦在于「能量都堆在少数几个通道」。如果我先把向量乘一个**正交旋转矩阵**（比如 Hadamard 矩阵），就能把这几个尖峰的能量**均匀打散到所有通道**，分布变得接近高斯——而高斯正是 INT8 最爱的「没有离群值」的分布。

关键魔法：旋转是正交的，`R·Rᵀ = I`，所以 `(Qᵀ R)(Rᵀ K) = Qᵀ K`，**点积结果完全不变**。Hadamard 变换还能用 `O(d log d)` 快速算法。

**用在 KV-Cache**：对 Q 和 K 各乘一个 Hadamard 旋转后再量化 K，**理论上能显著压低 K 的离群值**，且不改变注意力分数。这是当前学术界对付 outlier 最优雅、最有效的方向之一，**非常值得作为项目的一个高级特性来做**（哪怕只做离线的 fake-quant 版本验证收益）。

---

### 方案 E：裁剪 / 百分位标定（clipping）—— 主动「放弃」离群值

**直觉**：与其让一个离群值毁掉所有正常值，不如**直接把它截断**。比如 scale 不取 `max(|x|)`，而取 `99.9 百分位`。

- 好处：正常值的刻度立刻变细，精度大涨。
- 代价：被截断的离群值本身产生了「裁剪误差」。

这是一个**可调旋钮**：裁剪误差 vs 量化误差的权衡。可以做成「搜索最优裁剪阈值」（最小化 MSE 或对输出的影响）。**实现成本极低（只改 scale 的算法），建议立刻加上做消融**。

---

### 方案 F：INT8 / FP8 混合 —— 让数制各司其职

**直觉**：既然 V 分布温和、K 有离群通道，那就 **V 用 INT8（省、准），K 用 FP8（抗离群）**。或者反过来根据实测分布决定。

A100 对 FP8 的支持有限（FP8 的 tensor core 在 Hopper/H100 才完整），但我们可以**在内核里软件模拟 FP8 的 dequant**来做精度对照实验。CLAUDE.md 里本来就要求对照 FP8，这条正好落地。

---

### 小结：优先级建议

| 方案 | 精度收益 | 实现成本 | 是否动 INT8 内核数据通路 | 建议 |
|---|---|---|---|---|
| E 百分位裁剪 | 中 | **极低** | 否（只改 scale） | **立刻做** |
| B SmoothQuant（吸收进 Q） | 高 | 低 | 否 | **优先做** |
| A K 分组通道量化 | 高 | 中 | 是 | 做消融 |
| D Hadamard 旋转 | **很高** | 中高 | 否（Q/K 都转） | **亮点特性** |
| F INT8/FP8 混合 | 中高 | 中 | 是 | 对照实验 |
| C 混合精度分解 | 高 | 高 | 是（破坏带宽） | 仅作对照说明 |

## 3. 针对审稿意见其他问题的改进

### 3.1 问题一：只在 `N(0,1)` 合成数据上测 → 数据不够「真」

**为什么这是问题**：高斯数据是「无菌实验室」，没有真实模型那种重尾和离群通道。在它上面测出的 3% 误差，**系统性地低估**了真实退化。

**改进三步走（从易到难）**：

1. **注入离群值的合成压力测试**（最快）：
   - 重尾分布：用 Student-t（自由度小）代替高斯。
   - 离群通道注入：在 K 的少数固定通道上叠加大幅值（模拟 post-RoPE 的系统性离群），看误差怎么爆。
   - 这能在不跑大模型的情况下，**先把内核的脆弱点暴露出来**。

2. **抓真实分布做 fake-quant**（中等）：
   - 跑 Qwen2.5-1.5B 真实 prompt，**dump 出 post-RoPE 的 K 和 V 张量**，直接喂给我们的量化函数，看真实分布下的输出误差。

3. **端到端困惑度 / 任务精度**（最有说服力）：
   - 把 INT8 KV 做成 **fake-quant**（量化再反量化，插进 HF 推理路径），在 **WikiText-2 上测 perplexity**，在 **GSM8K 子集（200 题）上测 accuracy**。
   - 对照矩阵：`FP16 / FP8 / INT8-per-token / INT8-per-tensor / (+本文新方案)`。
   - 这正是 CLAUDE.md「Precision Evaluation」一节要求的，也是把「3% 误差」翻译成「困惑度只涨 0.05」这种**别人真正关心的语言**。

> ⚠️ 坑提醒（见项目记忆）：Qwen2.5 在 `do_sample=False` 下默认 `repetition_penalty=1.1`，会破坏纯贪心对比。测 perplexity / 贪心一致性时记得显式关掉。

---

### 3.2 问题二：误差指标有噪声 + 精度测试太松

**为什么是噪声**：我们现在用**逐元素相对误差** `|out_int8 - out_fp16| / |out_fp16|`。当 FP16 输出某个元素接近 0 时，分母趋近 0，相对误差**炸成天文数字**——所以报告里的「max 误差」基本是噪声，没有物理意义。而测试只卡了 `mean < 0.2` 且 `per_token <= per_tensor`，**随机数据闭着眼都能过**。

**改进：换成「整体向量」级别的指标**（这是业界标准做法）：

1. **余弦相似度（cosine similarity）**：只看方向对不对，不受逐元素零值影响。注意力输出方向对了，下游基本就稳。
   $$ \cos\theta = \frac{\langle o_{\text{int8}}, o_{\text{fp16}}\rangle}{\|o_{\text{int8}}\|\,\|o_{\text{fp16}}\|} $$

2. **范数归一化误差（norm-normalized / relative L2）**：用整个向量的范数当分母，**彻底避开单点除零**。
   $$ \text{rel} = \frac{\|o_{\text{int8}} - o_{\text{fp16}}\|_2}{\|o_{\text{fp16}}\|_2} $$

3. **收紧阈值**：在真实分布上跑出基线后，把 per-token 的阈值从「松松垮垮的 0.2」收到一个**真实分布下确实能区分好坏的值**（比如 cosine ≥ 0.999、rel-L2 ≤ 1e-2），让测试**真的有判别力**，而不是橡皮图章。

> 一句话：**别再用「会除以零的逐元素 max」当指标，改用「整条向量的 cosine + 相对 L2」。**

---

### 3.3 问题三：只有对称量化，没有零点（zero-point）

**为什么是问题**：对称量化假设数据**关于 0 对称**。高斯数据确实对称，所以现在没事。但真实分布（尤其 post-RoPE K）可能是**偏的（skewed）**，比如大部分值在 `[-1, 5]`。这时对称量化被迫用 `max(|x|)=5` 当范围，**整个负半轴 `[-5, -1]` 几乎没数据，等于浪费了一半 INT8 刻度**。

**非对称量化**引入零点 `z`，让量化范围贴合数据真实的 `[min, max]`：

$$ x \approx s \cdot (x_{\text{int}} - z), \qquad s = \frac{\max(x) - \min(x)}{255},\quad z = \text{round}\!\left(\frac{-\min(x)}{s}\right) $$

这样 255 个刻度全用在数据真正出现的区间上，**对偏分布精度收益明显**。

#### 关键：点积要加一个「修正项」（必须算清楚，否则结果错）

我们项目里 **Q 是 fp32、不量化，只有 K 进 INT8**。设对 K 用非对称、零点为 `z_k`、scale 为 `s_k`：

$$
\begin{aligned}
\text{score} &= \sum_d q[d]\cdot k_{\text{real}}[d]
= \sum_d q[d]\cdot s_k\,(k_{\text{int}}[d] - z_k) \\
&= s_k\Big(\underbrace{\sum_d q[d]\,k_{\text{int}}[d]}_{\text{现有 qk\_dot\_int8}}\;-\;z_k\underbrace{\sum_d q[d]}_{S_q}\Big)
\end{aligned}
$$

**好消息：这个修正项几乎免费。**

- `S_q = Σ_d q[d]` **只跟 Q 有关，每个 query 算一次**（head_dim 上一次归约），所有 key 共用。
- 对每个 key 只需多做一次标量运算：`s_k·(dot - z_k·S_q)`。

也就是说，在现有 `qk_dot_int8` 之外，只要：
1. 内核开头多算一个 `S_q`（一次 warp 归约）；
2. 每个 token 的分数公式从 `s_k·dot` 改成 `s_k·(dot - z_k·S_q)`。

**几乎不增加内层循环开销**，却能吃下偏分布的精度红利。V 的非对称类似，但 V 是和 softmax 权重做加权和，修正项形式略不同（`Σ_j p_j·s_v·(v_int - z_v)`，其中 `Σ_j p_j = 1`，所以修正项是 `-z_v·s_v`，更简单）。

**建议**：把非对称做成**可开关的 ablation**，在真实/偏分布数据上对比对称 vs 非对称的 cosine / rel-L2，用数据说话「这点额外开销值不值」。

## 4. 整合：一条推荐的进阶路线图

```
阶段 1（指标先立住，否则后面没法判断好坏）
  └─ 把误差指标换成 cosine + relative-L2 → verify: 旧测试重写，阈值收紧
阶段 2（暴露真实脆弱性）
  ├─ 合成数据注入离群通道 / 重尾 → verify: 看 INT8 误差是否随 outlier 显著恶化
  └─ dump Qwen2.5 真实 post-RoPE K/V → verify: 真实分布下的 cosine/rel-L2 基线
阶段 3（端到端的硬证据）
  └─ fake-quant 接入 HF，WikiText-2 PPL + GSM8K 200 题
     对照: FP16 / FP8 / INT8-per-token / INT8-per-tensor
阶段 4（真正提升精度的方案，按性价比上）
  ├─ 百分位裁剪（改 scale，极低成本）
  ├─ 非对称量化 + 点积修正项（内核小改，吃偏分布红利）
  ├─ SmoothQuant 系数吸收进 Q（不动 INT8 通路，压 K 离群通道）
  └─ Hadamard 旋转（项目亮点，把离群值摊平成高斯）
```

**一句话总结**：先把「尺子」（误差指标）和「考场」（真实/重尾数据 + 端到端 PPL）建对，再用「裁剪 → 非对称 → SmoothQuant → 旋转」这条由易到难的链条，系统性地解决 INT8 最怕的离群值问题。这样项目就从「在无菌高斯数据上误差 3%」升级成「在真实分布和困惑度上经得起检验、并主动攻克了 INT8 命门」的高水平工作。
```
